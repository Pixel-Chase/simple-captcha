架构与安全验证规范

自托管实例运行于内网或公网网关下，出题行为与二次验证遵循零信任凭证隔离原则：

v1.2.0 API 规范
1 前端出题 (Client Challenge)

前端 SDK 传入应用 ID (App ID)，系统校验来源请求头；仅在「允许来源」列表内的 Origin 允许获取题目与提交轨迹。

2 二次校验 (Server Verification)

业务后端调用接口 GET /api/v1/captchas/states/:key，请求头携带 Authorization: Bearer <应用密钥> 完成最终合法性确认。

! 安全防泄露原则 (Zero Trust)

停用、重置或删除后旧密钥立即失效并清理 Redis 缓存；密钥在生成时仅完整展示一次，后续永久遮蔽仅显示前缀。严禁将密钥暴露于前端代码。

rule 合规书写示范
  • 支持本地联调： http://localhost:3000 或 http://127.0.0.1:8080
  • 支持自定义端口： https://app.example.com:8443
  • 不支持路径 (Path)： 请勿输入 https://example.com/login
  • 不支持通配符 (Wildcard)： 安全策略禁止 *.example.com
